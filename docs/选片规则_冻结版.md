# 选片规则（冻结版 · core 2026.11.05.15）

> 本文是选片链的**唯一规格**。代码与本文不一致时，以本文为「意图」、以代码为「事实」，
> 差异必须回写到本文的「修订记录」，不允许只改代码不改文档。
> 对照实现：`src/songgrab_core.py`。

---

## 1. 搜索召回

- `SEARCH_API` 走 WBI 签名接口 `x/web-interface/wbi/search/type`；`_wbi_key` / `_wbi_sign` 负责签名，密钥缓存 6 小时。
- Cookie 预热：先访问 `https://www.bilibili.com/` 拿 `buvid3`，否则 412。
- 限流 1.2 s；412/429/503 退避重试 3 次（`sleep(1.5*(attempt+1))`）；同一关键词缓存 300 s。
- `search_both` = 音乐分区 `order=totalrank & tids=3`（命中标 `from_music=True`）
  + 综合区 `order=click`，按 bvid 去重合并（同 bvid 保留音乐分区那条）。
- 音乐分区用**综合排序**而不是播放量榜：热门词的正片在播放量榜会被生活/科普/鬼畜占满，进不了前 20。

## 2. 硬过滤链（`pick_card` 顺序执行，命中即剔除）

1. `match_rank > 0` 标题匹配（`_only_in_quotes` 放行日语「歌名」引用式标题）。
2. `TITLE_BLOCK` 非歌曲黑名单（教程/翻唱/解说/reaction/amv/mad/chart/anim/cover 等，英文加 `\b` 词边界）。
3. `_TITLE_INSTR_RX` 器乐改编硬剔（古筝/钢琴/鼓谱/贝斯/太鼓/双排键/电子琴/管风琴等）。
4. `_shell_of` 二创壳硬剔（`【X】歌名`，X 非歌名/技术词/曲库作者）；剔光则报「候选池无正片（全是鬼畜/二创壳）」。
5. `_REACTION_RX` 反应/解说/教学类剔（反应/盘点/为啥/秘闻/速学/教学/歌词分解等）。
6. `_KARAOKE_RX` 伴奏/消音/卡拉OK 剔。
7. 时长区间 `min_dur` / `max_dur`（默认 50 s / 720 s；时长 0 视为未知、放行）。
8. **`min_play` 播放量闸**：`play < min_play` 剔除；默认 `min_play = 1`，实际只挡 `play == 0`。
   *（补充 L13-2：此前规格漏写，代码一直生效。）*
9. `album_like` 专辑/合集剔（>25 min，或专辑词 + >8 min，或多P + 专辑词）。
10. 片段硬剔：`duration < ref_dur × 0.65`；剔光则报「候选池无正片（只剩切片/片段）」。
11. 超长剔：`duration > ref_dur × 1.6` 且（>900 s 或含循环/歌单/串烧/伴奏词）。
12. 候选全翻唱（`kinds` 全为 2）→ 报「候选池无正片（全是翻唱/器乐改编）」，不硬选。

> 第 4、10、11、12 步剔光时都返回失败而不是硬选，并把剩余候选（按播放量降序前 10）交给界面。

## 3. 加权评分（`_score`，v8 起播放量不进分）

```
基数 1.0
× _play_floor      (<1000→0.45 / <10000→0.65 / ≥10000→1.0 / ≤0→1.0)
× tag_score        (音乐标签 +0.05·n / 非音乐 −0.05·n，n 最多 3；夹 0.85–1.15)
× _title_weight    (title_score × clip_factor；情感号 ×0.6)
× _videos_factor   (多P ×0.8)
× up_score         (UP 主名含作者 ×1.10 / 搬运号 ×0.85)
× _music           (from_music ×1.5，否则 ×1.0，只加权不硬剔)
× (0.5 if artist_mismatch)
× (0.45 if 演奏者 kinds==1)
× (1.15 if 标题含曲库作者名 + 三选二交叉确认，canonical 可用时须对齐 canonical)
```

排序 key = `(非翻唱优先, 加权分, 播放量)`，`reverse=True`；同 UP 同名去重留播放最高。

**叠加额度（补充 L13-3）**：§6 的每类扣分**不是**按命中词数线性惩罚，而是每类最多算 N 次，
口径以代码为准（见 §6 表格「上限」列）；`tag_score` 的加分/扣分各自最多 3 次。

## 4. 优先级词条 / 高音质档

- **优先级词条（补充 L13-4）**：`DEFAULT_PRIORITY = []` 默认**空**，这一节在默认设置下不产生任何效果；
  只有用户显式写入词条时才生效。生效时按用户词条顺序，命中即取该组「加权排序第一」，按正则解释。
- **高音质档**：`from_music` 且标题含 Hi-Res/无损，加权分 ≥ 第一名 25% 即置顶。

## 5. 作者判定链（`describe_song`，最多 3 轮换候选）

1. 片段判定优先（`vdur < ref_dur × 0.65` 且 `_mode_n ≥ 2` → 换候选）。
2. `by_title`（`_name_in_title` 词边界命中，排除 `_NOT_ARTIST_RX` 厂牌/群星/合唱/feat）
   —— 标题作者 ≠ canonical，或命中厂牌名单 → 判翻唱、换候选。
3. `near`（众数簇内 ±5 s）。
4. `_mode_artist` 兜底（众数簇多源计数最多的作者）。
5. `artist_from_title` 兜底（`【X】` 或 `- 作者` 破折号结构）。

**时长冲突（补充 L13-5）**：标题里的作者若其曲库时长与 `ref_dur` 相差 >5 s，同样视为「不是这个人」→ 换候选。
该判据**仅在 canonical 锚点缺失时**生效；有硬锚点时以锚点为准，不再叠加时长冲突。

## 7. 关键锚点

- `_NOT_ARTIST_RX`：音阙诗听 / supercell / 众星 / 合唱 / 群星 / 电影原声 / 厂牌 / feat 等
  非个人演唱者，不参与 `by_title` 与作者加分。
- `_DASH_ARTIST_RX`：`- 作者` 结构放开到汉字/拉丁/假名 2–12 字符，支持 `·`、`&`。
- **canonical_artist 来源（L13 定稿）**：**只认用户用 `+` 写明的作者**（且必须通过 `artist_ok` 校验）。
  用户没写作者名时**不加锚点**。
  > 否决「用 QQ/网易云/Apple 五源众数当锚点」：曲库常把翻唱者当原唱返回，固定快照 100 首实测
  > bvid 命中 79% → 73%（硬锚点）/ 76%（软锚点，只用于加分对齐），净回退。
  > 锚点作用：`pick_card` 的 1.15 作者加分对齐、`choose_card` 换候选判据、`_dur_conflict` 关闭。


## 8. 试搜 → 确认 → 命名 → 下载（L14 定稿）

### 8.1 顺序
输入歌单 → **查作者**（音乐平台）→ **带作者搜 B 站** → 分档展示 → 用户确认 →
命名 → **只下载已确定音源**（下载阶段不再搜索，直接按所选 bvid 取流 + 重封装）。

### 8.2 作者来源
| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 用户 `+` 写明的作者 | 豁免平台查询 |
| 2 | QQ 音乐 | 取返回列表**第一条** |
| 3 | Apple Music | 按歌名字体：繁体 → tw/hk 同级；日语 → jp 优先 |
| 4 | 网易云 | |
- 每个源只取**返回列表第一条**（接口无播放量字段，取不到「最高播放量」）。
- 作者**只用于搜索关键词 + 命名**，不当换候选锚点（§7 已否决）。

### 8.3 分支判定（计数点 = **最终真正参与排序的池子**，软回退后为准）
- **分支 1**：过滤后 **>5 条** 且 **≥2 条播放量 >1 万**（1 万门槛只用于此判定，不改 `min_play`）。
  - 1a **完全命中**：标题同时含完整歌名 + 作者，且加权排序**无并列第一** → 成功类（可展开）。
  - 1b 其余 → 待确认，取加权分**前三**做候选。
- **分支 2**：过滤后 ≤5 条（或只有 1 条 >1 万）→ 静默回退**不带作者**再搜，
  与带作者结果**取并集**（不替换）→ 待确认；仍 0 条 → 失败「无搜索结果」。
- 分支 1 过滤后 0 条 → 直接走分支 2。平台查不到作者 → 直接走分支 2。
- `+` 切作者：默认从**最后一个** `+` 切；结果 <5 条则往倒数第二个切，依此类推。

### 8.4 白名单（优先级高于完全命中）
`JLRS日落fm` / `JLRS-LeoFM` / `JLRS-jayfm`，**UP 主名精确匹配完全一致**（不做包含）。
豁免条件：**标题必须完整带歌名**（简介带不算）。其余过滤全豁免，**仍过 min_dur/max_dur**。

**L15 取消条件**：标题命中下列任一词条 → 该视频**取消白名单优先**，回到正常筛选顺序
（`core.wl_blocked()` / `WL_BLOCK_RX`，中文词条包含匹配，英文词条加词边界防误伤）：

- 合唱类：合唱、合唱版、三人合唱、多人合唱、大合唱、万人合唱、接力合唱、接龙、全员合唱、群星、分声部、多声部、三声部、混声合唱、轮唱、和声、伴唱、阿卡贝拉、无伴奏、纯人声、单人阿卡贝拉
- 翻唱类：翻唱、cover、翻唱版、男声版、女声版、童声版、戏腔版、升key、降key、变速、加速、清唱、试唱、demo、纯享版
- 现场/改编类：现场版、舞台版、导师互唱、改编、重编曲、混音、填词、中文填词、翻填、空耳、串烧、组曲、mashup、重置版
- 器乐/无人声类：伴奏、消音、纯音乐、无人声、卡拉OK、演奏、钢琴版、指弹、民乐版、古筝、纯器乐
- 二创/调教类：调教、声库、AI翻唱、AI音乐、ACE、DiffSinger、鬼畜调教、音MAD、人力VOCALOID、MMD

命中被取消时向通知栏报一句「白名单 UP 有 N 条视频标题含合唱/翻唱/改编等词，已取消其优先，改走正常筛选」。

### 8.5 结果框与确认
- 三档：成功（已确定音源）/ 待确认 / 失败；确认完刷新为「成功有名 / 成功无名 / 失败」。
- 待确认：候选卡显示**标题 / UP 主 / 播放量 / 时长**；再次左键单击确认，右键取消。
- 主界面常驻「跳过未确定项」：点击**立刻**把剩余待确认项转失败并重排。
- 失败项带原因标签：无搜索结果 / 用户跳过 / 下载失败。
- 成功项右键「重新试搜此条」可回退重搜。

### 8.6 命名
- 有作者：单点弹窗可改歌名/作者（只改显示名与文件名，**不重新搜索**）。
- 无作者：标「未命名」；下载前弹窗，含「上一项 / 下一项 / 跳过全部」。
- `Unknown` 只在命名环节结束仍未命名的项才标。
- 同一首歌在歌单出现两次 → 合并为一次。
- 状态落盘 `confirm.json`（含 status/reason/source），重开程序保留。

### 8.7 运行
- 平台查询并发（5 源已并行），**B 站请求仍全局串行**（`_MIN_INTERVAL=1.2`，防 412）。
- 进度条 + 暂停键（暂停只在两首之间生效）+ 通知栏提示语。
