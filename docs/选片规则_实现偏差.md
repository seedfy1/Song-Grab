# 选片规则实现偏差记录

冻结规格：`docs/选片规则_冻结版.md`（sha256 `3a6715f3…`，逐字节冻结，不随代码修改）。
本文件按规格 §0「差异必须回写」的要求记录**实现侧**与规格的偏差。
规格文件本身不动，这里的条目只描述实现现状。

当前实现：`src/songgrab_core.py`（唯一实现，移植自 Windows 版 `song-grab1` v1.1.3）。

> 2026-11-14 换引擎后，`src/picker.py` 与 `src/metasrc.py` 已删除——选片链
> （`pick_card`）与曲库查作者（`lookup_artist_priority`）都并入了 core。
> 下表描述的是 core 里的实现现状。

| # | 规格位置 | 规格要求 | 实现现状 | 影响 |
|---|---|---|---|---|
| 1 | §2 ① | `_only_in_quotes` 放行日语「歌名」 | 未单独实现；引号包裹的候选由 `match_rank` 直接判为 3 级并放行，非引号的模糊匹配不作额外收紧 | 日语标题可能出现更多弱匹配候选（靠加权分与作者链兜底） |
| 2 | §8.7 | 平台查询并发 | `lookup_artist_priority` 单线程串行（B站曲库 → QQ → Apple → 网易云，命中即止） | 最多多花 2 次网络往返 |
| 3 | §8.7 | 进度条 + 暂停键 | 有进度条；**没有暂停键**，只有「停止」 | 停止为当前曲目下完即停，不支持恢复 |
| 4 | §1 | 同关键词缓存 300s | 已实现；但**空结果不入缓存**（B站风控时会返回 code=0 + 空列表，缓存会毒化后续请求） | 风控后立刻重试不会被缓存挡住 |
| 5 | §2 ④ | `_shell_of` 技术词判定 | 除整词匹配外，额外把「4K修复」「完整版官方」这类组合前缀逐个剥掉再判断 | 避免把「【4K修复】歌名」误判成二创壳 |
| 6 | §4 高音质档 | from_music + Hi-Res/无损 + 加权 ≥ 第一名 25% 置顶 | 已实现，作为兜底档（优先词不命中时才走） | — |
| 7 | §8.3 | `+` 切作者从最后一个 `+` 切 | 已实现（`parse_song_entry` 用 `rsplit`，支持全角 `＋`） | 歌名自带 `+` 时行为符合规格 |
| 8 | §8.5 | 三档结果框 + 待确认候选卡 + 跳过未确定项 | 已实现：试搜弹三档；待确认行为琥珀色可点选候选；底栏「未确认：跳过 / 也下」开关；待确认曲目**不进入下载** | — |
| 9 | §8.6 | 有作者可改、无作者标未命名 | 已实现：试搜弹窗里「曲师：XXX（来源）  改」可点，改完立刻重绘；留空 = 主动清空，下载阶段**不查作者**，标签记 `Unknown` | — |
| 10 | §8.6 | 待确认状态落盘 `confirm.json` | 已实现：`core.load_confirm/save_confirm/clear_confirm`，`raw -> {bvid, artist, title, lock, src_artist, t}`，保留最近 500 条；App 启动时还原，设置页有「忘掉已确认的音源」 | — |
| 11 | §8.1 | 只下载已确定音源 | 已实现：确认后带 `bvid` 直下，下载阶段不再搜索；若稿件被删（`video_info` 返回空）自动退回重新试搜 | — |
| 12 | §8.6 | 「只改显示名与文件名」（作者参与文件名） | **文件名只用歌名**（`晴天.m4a`），作者不参与文件名，改为写入音频标签 `title` / `artist` / `album_artist`；曲师缺失或用户清空时标签记 `Unknown` | 与规格字面不符，但标签里作者信息完整，播放器按标签显示；同名不同版本会被 `find_existing` 视作已存在 |
| 13 | §2 硬过滤 | 一律按「正片」过滤，剔光报失败 | **歌名里自己写了翻唱/现场/伴奏/器乐/remix 这类词时**（`songgrab_core._USER_WANT_RX`）跳过「非正片黑名单 / 器乐 / 二创壳 / 反应 / 伴奏」五道内容过滤，只保留时长·播放量·专辑·片段闸 | 用户明确要这个版本时不会被自己的意图挡住 |
| 14 | §2 末 | 全是翻唱/器乐 → 判失败 | **不再判失败**：全翻唱时把加权前三交出来待确认；任何一步硬过滤把池子剔光时，退回「标题含歌名」的全集按分排序给前三条 | 用户要的是「能挑」，宁可多给候选也不 0 结果 |

## 未做的（规格提到、实现没有）

- 同歌重复合并（§8.6）：靠 `find_existing` 按文件名前缀跳过，未做同名多版本合并。

## 换引擎（2026-11-14）顺带带来的能力

规格里没写、但 Windows 版早就有的工程能力，这次一并同步：

- **断点续传**：`resume.json` 记录每首的进度，停止后重开接着下
- **完整性校验**：`audio_ok` / `video_ok` 校验体积落在「码率 × 时长」0.7–1.2 倍内、
  转封装后时长差 ≤5 秒，不达标删文件记失败（防下载被截断却当成功）
- **目录对账**：`reconcile_compare` 启动时核对磁盘与 `catalog.json`，产出 `compare.json`
- **known_good / known_bad**：记住某首歌的正确 BV，被删稿件自动拉黑并重搜
- **故障统计**：`metrics_event` 流水 → `metrics_export_csv` / `export_need_author`
- **输出格式三态**：m4a / mp3(320k) / mp4
- **失败原因分类**：`fail_label` 给出 12 类中文原因
